# PICO 4: seating, microphone and conversation

## Confirmed causes

- The shipped APK included `libgirlfriend_ai.so` but omitted its `DT_NEEDED`
  dependency `libc++_shared.so`. Device startup logged a native load failure and
  silently switched to `MockLocalLLM`; the panel still said `Ready`. This explains
  the canned responses and 0 ms inference shown in the supplied photograph.
- Sherpa 0.2.0 only auto-drains VAD segments while speech is active. The final
  segment after silence could remain queued until another utterance. The app
  also stopped capture for the entire reply/action sequence, and flushing on stop
  would emit unfinished speech.
- Seat anchors assumed local Y was height and local Z was depth, then copied the
  full captured rotation into the avatar. Legacy PICO volume axes can be tilted
  relative to world up. A fixed 180-degree rotation cannot correct that basis.
- The Humanoid Animator used `CullUpdateTransforms`, freezing its bones outside
  the camera view while seating still read the hips. It now always updates the
  single companion's animation; rendering/LOD culling remains enabled.

## Changes

- Package the matching NDK C++ runtime and validate its Android importer at build.
  Device builds preserve real LLM errors instead of silently substituting mock
  commands. Editor mock mode is clearly labelled.
- Use a conversational Qwen prompt, an empty thinking prefix, 4096 context tokens,
  384 output tokens, and native JSON grammar with optional actions. Arbitrary user
  questions reach the LLM; physical actions still pass the existing whitelist.
- Drain VAD after each complete window, reset partial audio on mute/pause, discard
  ASR completed after mute, and resume capture after transcription. Recognized
  text and microphone level/status appear in diagnostics. Playback is excluded
  from VAD; no acoustic echo canceller or interruption during spoken playback is
  implemented.
- X on the left controller toggles mute, with a brief haptic pulse. A vector mic
  icon follows the HMD at lower left: green when recording, red/crossed when muted,
  amber while unavailable/starting. Changes brighten it temporarily; mute remains
  visible. The existing right A menu binding is retained. The HUD is attached by
  the voice component in existing scenes.
- Build a level seat frame from the world-space box axes. The shorter horizontal
  axis supplies depth; its side toward the headset at room-query time supplies
  front/back. Approach, cushion position and facing share that frame. Box bounds
  do not encode backrest direction, so capture from the usable side of the sofa.
- Prevent cancelled requests from clearing a newer request's speaking state or
  releasing its audio clip; defer native shutdown until inference releases its gate.

  mute discard, and conversation with an empty room and no actions.

- Real PICO 4 native smoke: `INIT=0`, `GENERATE=0`; Qwen produced Russian speech and
  `actions: []` for a conversational question.
- Bridge rebuilt with the pinned NDK/llama.cpp and 16 KiB ELF load alignment.
- Release APK 0.2.1 (Android version code 3) built successfully with Unity
  6000.3.23f1. APK inspection confirms both the bridge and `libc++_shared.so`

- Installed over the existing app on the connected PICO 4 with `adb install -r`;

  updated APK's live microphone/controller/room acceptance awaits the user's
  headset check; do not treat the native smoke as a complete voice-path test.

## Follow-up: command regression reported on 2026-09-06

The user reported that both menu buttons and voice commands stopped working in
0.2.1. Code inspection found that every menu command went through neural generation,
and microphone delivery depended on `GirlBrain.IsReady`, including model readiness.
Removing silent mock fallback exposed this shared dependency. The precise runtime
LLM failure/latency is still under device investigation; this dependency alone
does not establish why generation failed on that run.

- Menu buttons now submit explicit actions through the existing action validator
  and executor. Complete imperative phrases in Russian and English use the same
  path. Negations, questions and other conversation still reach the LLM.
- Room/navigation, UI and command handling initialize before the conversation
  model. Voice transcripts can deliver commands while the model loads or is
  unavailable. A new command cancels a pending conversation without waiting for
  inference or voice synthesis.
- Diagnostics show model loading/generation separately from command availability,
  generation elapsed time, explicit request results and native error meanings.
- EditMode: 43/43 passed (`Builds/editmode-command-fixes.xml`), including commands
  without a model and cancellation of pending inference.
- PlayMode: 2/2 passed (`Builds/playmode-command-fixes.xml`), including the complete
  motion sequence and seated-knee alignment.
- APK 0.2.2 / code 4 built successfully (`Logs/pico-command-fixes-build.log`) and
  installed with `adb install -r`, preserving app data. Both native bridge and C++
  dependency are present in the APK. Android grants `RECORD_AUDIO` and app-ops
  allows recording. Device startup still waits at the PICO system boundary
  confirmation screen; full installed-app acceptance is pending.

## Remaining project-wide findings

The runtime has separate room, navigation, inference, voice and memory boundaries;
that structure supports these fixes without replacing the application. Existing
architecture/status documents predate the authored Humanoid animations and
Supertonic TTS and should not be treated as current verification evidence.

The bundled 0.6B model can give awkward Russian answers even when inference works.
The native smoke verifies execution and output shape, not conversation quality.
Seating height is estimated from the furniture box, not an explicitly captured
cushion plane. Physical alignment, controller comfort, background noise and long
session behavior still require checks in the user's room.
